# ADR 001: رزرو اتمیک موجودی (Atomic Inventory Reservation)

- **وضعیت (Status):** پذیرفته‌شده (Accepted)
- **زمینه (Context):** سامانه باید بتواند موجودی محصولات را رزرو کند، بدون اینکه مقدار `RemainingStock` منفی شود؛ حتی زمانی که چند درخواست به‌صورت هم‌زمان ارسال می‌شوند.

## تصمیم معماری (Decision)

در Endpoint مربوط به رزرو، از یک دستور شرطی `SQL UPDATE` استفاده می‌شود. این دستور فقط زمانی `RemainingStock` را کاهش می‌دهد که رویداد فروش متعلق به `Tenant` درخواست‌شده باشد، در بازه‌ی زمانی فعال قرار داشته باشد و موجودی کافی داشته باشد.

کاهش موجودی و ثبت رکورد `Reservation` در یک `Database Transaction` انجام می‌شوند.

## پیامدها (Consequences)

- دستور شرطی `UPDATE` از رزرو بیش از موجودی، هنگام ارسال درخواست‌های هم‌زمان، جلوگیری می‌کند.
- استفاده از `Database Transaction` به حفظ سازگاری بین تغییر موجودی و ثبت رکورد رزرو کمک می‌کند.
- اجرای این راهکار به دیتابیس و تراکنش‌های `SQL Server` وابسته است.
- برای اطمینان از عملکرد صحیح در شرایط بار و درخواست‌های هم‌زمان، انجام `Concurrency Testing` خودکار ضروری است.

## گزینه‌های بررسی‌شده (Alternatives Considered)

- خواندن موجودی در حافظه‌ی برنامه و سپس به‌روزرسانی آن انتخاب نشد؛ زیرا ممکن است چند درخواست هم‌زمان مقدار یکسانی از موجودی را مشاهده کنند و باعث رزرو بیش از حد شوند.
- استفاده از `Distributed Lock` انتخاب نشد؛ زیرا در پیاده‌سازی فعلی می‌توان شرط موجودی را مستقیماً در `SQL Server` اعمال کرد.
