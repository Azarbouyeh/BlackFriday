# Black Friday Sale Reservation Service

## 1. معرفی پروژه

این پروژه یک REST API برای مدیریت رویدادهای فروش ویژه و رزرو موجودی محصولات با پشتیبانی از Multi-Tenancy است. هدف اصلی، جلوگیری از Overselling و اطمینان از جداسازی داده‌های Tenantها است.

**فناوری‌های استفاده‌شده:**
- C#
- ASP.NET Core Web API
- Entity Framework Core
- SQL Server
- Swagger / OpenAPI

## 2. قابلیت‌های پیاده‌سازی‌شده

- دریافت رویدادهای فروش بر اساس `TenantId`.
- ایجاد رزرو برای رویداد فروش فعال.
- کاهش اتمیک موجودی با استفاده از شرط در دستور SQL.
- استفاده از Database Transaction برای کاهش موجودی و ثبت رزرو.
- جلوگیری از رزرو در صورت اتمام موجودی، غیرفعال بودن رویداد یا عدم تطابق Tenant.
- ایجاد داده‌های اولیه برای دو Tenant شامل رویدادهای فعال، آینده و منقضی‌شده.

## 3. API Endpoints

### دریافت رویدادهای فروش

`GET /api/tenants/{tenantId}/sale-events`

فهرست رویدادهای فروش مربوط به Tenant مشخص‌شده را برمی‌گرداند.

### ایجاد رزرو

`POST /api/tenants/{tenantId}/reservations`

نمونه‌ی درخواست:

```json
{
  "saleEventId": 1
}
```

در صورت موفقیت، اطلاعات رزرو ایجادشده برگردانده می‌شود. اگر رویداد قابل رزرو نباشد یا موجودی کافی نباشد، پاسخ `409 Conflict` داده می‌شود.

## 4. تصمیم معماری: جلوگیری از Overselling

کاهش موجودی با یک دستور شرطی SQL انجام می‌شود که فقط زمانی موجودی را کاهش می‌دهد که:

- شناسه‌ی رویداد و Tenant مطابقت داشته باشند.
- موجودی بیشتر از صفر باشد.
- رویداد در بازه‌ی زمانی فعال قرار داشته باشد.

سپس ثبت رزرو و کاهش موجودی در یک تراکنش دیتابیس انجام می‌شوند. این روش احتمال رزرو بیش از موجودی را در درخواست‌های هم‌زمان کاهش می‌دهد.

## 5. اجرای محلی

1. اجرای SQL Server
2. تنظیم `DefaultConnection`  در `appsettings.json`
3. اعمال Migrationهای Entity Framework Core  روی دیتابیس .
4. اجرای پروژه در Visual Studio
5. استفاده از Swagger برای مشاهده و تست Endpointها 

## 6. وضعیت اعتبارسنجی

موارد زیر به‌صورت دستی آزمایش شده‌اند:

- اجرای موفق پروژه و Build.
- دریافت فهرست رویدادهای فروش از طریق Swagger.
- ایجاد رزرو موفق با پاسخ HTTP 200.
- کاهش موجودی پس از ایجاد رزرو.
- رد درخواست رزرو با Tenant نامنطبق با پاسخ HTTP 409.

7. محدودیت‌ها و کارهای باقی‌مانده
اجرای هم‌زمان درخواست‌ها هنوز با تست خودکار یا اسکریپت اختصاصی اعتبارسنجی نشده است.
BackgroundService برای پردازش سفارش‌ها پیاده‌سازی نشده است.
Retry و Dead Letter Queue پیاده‌سازی نشده‌اند.
Docker Compose برای اجرای SQL Server آماده نشده است.
ارتقا به .NET 8 یا بالاتر هنوز انجام نشده است.
